Embed production-grade school bus tracking in Flutter.

A plug-and-play Flutter library for real-time school bus tracking in parent-facing mobile apps. Drop it in and ship live GPS tracking, animated maps, and push notifications in minutes.

Flutter 3.19+ Framework constraint
Dart 3.0+ Language baseline
Android 24+ Min Android SDK
iOS 12+ Min Deployment Target

Key Features

🎬

Smooth 60fps Animation

Frame-independent bus movement interpolation on Google Maps.

🛣️

Intelligent Routing

Automatic polyline rendering with path-snapping to roads.

⏱️

Real-time ETA

Dynamic arrival time calculation for pickup and drop-off.

🔥

Consumer-owned Firebase

Reuses your default Firebase app for reliable FCM delivery.

🔄

Session Management

Auto token refresh and persistent user sessions baked in.

🔔

Push Notifications

FCM notifications with deep-link to live tracking screen.

Getting Started

Installation

Pull the SDK directly from the private Cloudsmith repository. These instructions apply to SDK version ≥ 2.15.

🔒
Authentication Required
This is a private package repository. You must store an API key credential locally before installing.
API Key

Using the CLI (Recommended)

1

Step 1 — Store your API key

Run this once to save your credentials. Replace YOUR-API-KEY with the key from your iCue dashboard:

Terminal (bash) 
echo 'YOUR-API-KEY' | dart pub token add https://dart.cloudsmith.io/icue/icue-sdk/
2

Step 2 — Add the dependency

Use dart pub add to add the package to pubspec.yaml and install it in one command:

Terminal (bash) 
dart pub add icue_sdk --hosted-url https://dart.cloudsmith.io/icue/icue-sdk/
🔑
Don't have an API key?
Contact iCue support to get your credentials:
✉️ chakri@thoughtniques.com 📱 +91 77999 20206

Manual pubspec.yaml

Alternatively, edit pubspec.yaml by hand and run flutter pub get:

pubspec.yaml 
dependencies:
  flutter:
    sdk: flutter
  icue_sdk:
    hosted:
      name: icue_sdk
      url: https://dart.cloudsmith.io/icue/icue-sdk/
    version: ^0.1.0
Terminal (bash) 
flutter pub get

Platform Setup

Android Configuration

Three changes are required in your Android project before the SDK will run correctly.

1

Add Manifest Permissions

Open android/app/src/main/AndroidManifest.xml and add these permissions inside the root <manifest> tag:

AndroidManifest.xml 
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
2

Add Google Maps API Key

Inside the <application> tag, add your Maps API key:

AndroidManifest.xml 
<meta-data
    android:name="com.google.android.geo.API_KEY"
    android:value="YOUR_GOOGLE_MAPS_API_KEY" />
🔐
Key Security: Restrict your Android Maps API key in the Google Cloud Console to your Android package name and SHA-1 signing certificate fingerprint.
3

Set Minimum SDK Version

In android/app/build.gradle, ensure minSdkVersion is at least 24:

android/app/build.gradle 
defaultConfig {
    minSdkVersion 24  // minimum required by iCue SDK
}

Platform Setup

iOS Configuration

Two changes are required in your iOS project before the SDK will run correctly.

1

Add Location Permissions

In ios/Runner/Info.plist, add the location usage description:

ios/Runner/Info.plist 
<key>NSLocationWhenInUseUsageDescription</key>
<string>We need your location to show how far you are from the school bus.</string>
2

Initialize Google Maps

In ios/Runner/AppDelegate.swift, call GMSServices.provideAPIKey before the app launches:

AppDelegate.swift 
import UIKit
import Flutter
import GoogleMaps

@UIApplicationMain
@objc class AppDelegate: FlutterAppDelegate {
  override func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
  ) -> Bool {
    GMSServices.provideAPIKey("YOUR_GOOGLE_MAPS_API_KEY")
    return super.application(application, didFinishLaunchingWithOptions: launchOptions)
  }
}
🔐
Key Restriction: Restrict your iOS Maps API key in Google Cloud Console to your iOS bundle identifier.

Integration

Initialization

Set up the SDK once at app startup. Two steps are required — both must complete before you call any other SDK methods.

1

Initialize the SDK

Call IcueSdk.init and await it before runApp. This sets up authentication, networking, and notification listeners:

lib/main.dart 
import 'package:flutter/material.dart';
import 'package:icue_sdk/icue_sdk.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  await IcueSdk.init(
    const IcueSdkConfig(
      apiKey: 'YOUR_API_KEY',
      apiUser: 'YOUR_API_USER',
      env: IcueEnvironment.prod, // Use IcueEnvironment.dev for testing
    ),
  );

  runApp(const MyApp());
}
2

Register the Navigator Key

The SDK navigates between screens when users tap push notifications. Provide IcueSdk.navigatorKey to your MaterialApp:

lib/main.dart 
MaterialApp(
  navigatorKey: IcueSdk.navigatorKey,
  // ... rest of your config
);
💡
Custom Navigator Key: Already using a custom GlobalKey<NavigatorState>? Register it with IcueSdk.setNavigatorKey(myKey) instead.

Integration

Live Tracking

Open the animated real-time tracking screen for any student with a single method call. The SDK handles all map rendering, animation, and ETA display internally.

Open the Tracking Screen

Pass a valid student ID (identificationNo) to launch the tracking view from any BuildContext in your app:

lib/main.dart 
IcueSdk.openLiveTracking(
  context,
  identificationNo: '12345', // Student identification number
);
ℹ️
The identificationNo is the student's unique ID in the iCue system. Contact iCue support if you are unsure what value to use.

Integration

Push Notifications

Enable Firebase Cloud Messaging so iCue can alert parents and open live tracking directly when a notification is tapped.

🔔
The SDK uses Firebase Messaging on the default Firebase app. If your app already initializes Firebase, the SDK reuses it automatically. If not, pass IcueFirebaseOptions and the SDK initializes the default app for you.

Prerequisites

Required Item What to Prepare
Firebase Project Create or choose the Firebase project that belongs to the consumer app. Add the Android package name and iOS bundle ID used by your app.
Service Account JSON In Firebase Console → Project Settings → Service Accounts → Firebase Admin SDK, click Generate new private key. Email the JSON to chakri@thoughtniques.com so iCue can configure server-side FCM delivery.
iOS APNs Setup For iOS, upload an APNs authentication key or certificate in Firebase Console before testing push on a real device.
⛔
Keep the service account JSON secret. Do not commit it to source control, paste it into tickets, or share it in public channels. Send it only from an authorized business email.

Setup Steps

1

Create or Choose a Firebase Project

Use the Firebase project that will send push notifications for the consumer app. Add both Android and iOS apps in Firebase with the same package name / bundle ID used by your Flutter app.

⚠️
iCue can only send notifications to FCM tokens from this Firebase project after the iCue backend is configured with this project's credentials. Share the project details with iCue support before production testing.
2

Add Firebase Packages & Generate Options

Add Firebase dependencies and generate lib/firebase_options.dart using FlutterFire CLI:

Terminal (bash) 
flutter pub add firebase_core firebase_messaging
dart pub global activate flutterfire_cli
flutterfire configure

This creates platform config files: android/app/google-services.json, ios/Runner/GoogleService-Info.plist, and lib/firebase_options.dart.

3

Complete Android FCM Setup

Confirm the Google Services plugin is applied and the Android 13+ notification permission is declared:

android/settings.gradle.kts & app/build.gradle.kts 
// android/settings.gradle.kts
plugins {
    id("com.google.gms.google-services") version("4.3.15") apply false
}

// android/app/build.gradle.kts
plugins {
    id("com.google.gms.google-services")
}
AndroidManifest.xml 
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

Keep android/app/google-services.json in the app module. The SDK requests notification permission at runtime during initialization.

4

Complete iOS FCM Setup

Add GoogleService-Info.plist to the Runner target, enable push capabilities, and allow background remote notifications in Info.plist:

ios/Runner/Info.plist 
<key>UIBackgroundModes</key>
<array>
  <string>remote-notification</string>
</array>

In Xcode, enable Push Notifications and Background Modes → Remote notifications for the Runner target. Upload the APNs key or certificate to Firebase Console. Test iOS push notifications on a real device.

5

Pass Firebase Options to the SDK

If your app does not call Firebase.initializeApp itself, pass the generated platform options to IcueSdk.init:

lib/main.dart 
import 'package:flutter/material.dart';
import 'package:icue_sdk/icue_sdk.dart';
import 'firebase_options.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  await IcueSdk.init(
    const IcueSdkConfig(
      apiKey: 'YOUR_API_KEY',
      apiUser: 'YOUR_API_USER',
      env: IcueEnvironment.prod,
      firebaseOptions: IcueFirebaseOptions(
        android: DefaultFirebaseOptions.android,
        ios: DefaultFirebaseOptions.ios,
      ),
    ),
  );

  runApp(const MyApp());
}
💡
If your app already initializes Firebase before IcueSdk.init, the SDK reuses that default app and uses it to read FCM tokens and message streams — no extra configuration needed.
6

Register the Navigator Key

Notification taps are handled without a visible BuildContext, so the SDK needs a navigator key:

lib/main.dart 
MaterialApp(
  navigatorKey: IcueSdk.navigatorKey,
  // routes, theme, home, etc.
);

If your app already has a navigator key, call IcueSdk.setNavigatorKey(myNavigatorKey) before notifications are tapped.

7

Open Tracking to Register the Token

The SDK fetches the FCM token during initialization and registers it with iCue after student authentication. Open live tracking at least once per student during setup or normal use:

lib/main.dart 
IcueSdk.openLiveTracking(
  context,
  identificationNo: 'STUDENT_IDENTIFICATION_NO',
);

Watch logs for FCM SERVER TOKEN and updateRegTokens while testing.

8

Send the Notification Payload

Include StudentId in the FCM data payload. When the user taps the notification, the SDK opens live tracking for that student via IcueSdk.openLiveTrackingFromRoot:

FCM Payload (json) 
{
  "notification": {
    "title": "Bus Update",
    "body": "Tap to open live tracking"
  },
  "data": {
    "StudentId": "STUDENT_IDENTIFICATION_NO",
    "action": "live_tracking"
  }
}

The action field is optional today, but keeping it in the payload makes future routing rules easier to support.

Verification Checklist

✓
Firebase app initializes — No default Firebase app errors in app logs.
✓
Permission is requested — Android 13+ or iOS prompts the user for notification permission.
✓
Token is created — Logs show FCM SERVER TOKEN.
✓
Token reaches iCue — After live tracking auth, updateRegTokens succeeds.
✓
Tap opens tracking — Notification tap opens the SDK tracking screen for the correct StudentId.

Troubleshooting

Common issues and how to resolve them quickly.

Symptom Resolution
"No Config" in logs Ensure IcueSdk.init is fully awaited before calling any tracking features.
Blank map tiles Verify the Google Maps SDK is enabled in Google Cloud Console and billing is active on your project.
No location shown Ensure runtime location permissions are requested in your app flow and explicitly granted by the user.
FCM token not registered Open live tracking for the student at least once. The token registers only after the student is authenticated by the SDK.
Notification tap does nothing Confirm IcueSdk.navigatorKey (or setNavigatorKey) is set before the app handles a notification tap.
iOS push not received Verify APNs key/certificate is uploaded to Firebase Console and test on a real device — simulators do not receive push notifications.
